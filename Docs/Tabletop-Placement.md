# 桌面吸附（0.5.6）

## 使用

允许应用访问空间数据，缓慢看过茶几表面及边缘。用现有双手捏合缩小展台，再将铁轨底部移近茶几。铁轨、操作台、零件盘作为一个整体贴桌；双手仍可平移、绕 Y 轴旋转和缩放。向上累计提起约 5.5 厘米才会脱离，松手固定。单手移动把手也使用同一吸附规则。

默认轨道长约 2.4 米；缩至现有下限 26% 时，三个主体的整体范围约宽 0.624 米、深 0.211 米。不会自动更改用户的缩放。桌面支撑不足时显示缩小/移向中央提示；已贴桌时，超出桌边的移动或放大保留最后一次受支撑的位置，先提起即可移走。

## 感知路径与限制

- 工程版本保持 Unity 2022.3.62f2c1、SpatialAdapter 6.1.0、PICO XR 6.1.1、AR Foundation 5.1.5；仍为现有 Mixed Stage 和原生 Spatial 渲染。
- 已安装 SDK 的 `PXR_Loader` 在 `PICO_MS_SDK` 分支没有建立独立 PlaneDetection provider，不能直接套用普通 XR 模式的 `PXR_MixedReality.StartSenseDataProvider(PlaneDetection)`。
- 使用 SDK 已接入 Spatial 模式的房间网格：Unity 公开 `XRMeshSubsystemDescriptor` 查找/创建 `PICO Mesh`，订阅公开 `PXR_Manager.SpatialMeshDataUpdated`。此路径由 SDK 的 Spatial 输入 Loader 转发真实扫描网格和逐顶点语义。
- 0.5.1 真机启动证实存在两个同名 `PICO Mesh` 描述符，第一个 `Create()` 返回 null。0.5.2 会尝试其余同名提供器，并在 Stage 初始化期间最多重试三次。接口名称存在不代表实例创建成功，也不代表桌面检测成功，必须分别验证。
- `SwanTableSurface` 仅接收 Table 标签，提取朝上的近水平三角形，排除地面、墙面、未知标签、桌腿与桌板背面。网格位置和旋转已经由 SDK 转为 Unity 坐标，只应用一次网格姿态。
- 这属于**从真实语义网格提取桌面**，不宣称使用独立平面锚点 API。茶几的语义与网格覆盖必须由真机验证；未识别到 Table 时不会猜测桌面高度。
- 不创建可见房间网格或环境碰撞器，不阻挡机车操作。无跨重启持久化；不读摄像头图像。

## 交互规则

- `SwanTabletopBuild` 以原轨道底部为基准，对齐操作台与零件盘底部；派生场景中的下方按钮抬至桌面之上。搭档原场景保持原样。
- 轨道、操作台和零件盘各自采样 15 个支撑点，按当前旋转与缩放检查真实扫描面的覆盖。0.5.5 要求**每一组**至少 12/15 点有效，并且该组中心有效；不以全场总覆盖率替代单个物件的支撑。支撑点距同高度真实扫描三角形边缘最多 5 厘米，高度误差最多 3 厘米；中心允许 3.5 厘米扫描缝隙。少量边缘缺口/悬出不再一票否决，较大悬空、中心空洞、不同高度仍拒绝。此规则用于 MR 摆放，不是严格物理碰撞边界。
- 底部距扫描桌面不超过 6.5 厘米时吸附，保留 4 毫米间隙；改变缩放仍按实际底部偏移对齐。
- 双手中心或单手把手的真实手部位移驱动提起阈值。累计向上 5.5 厘米脱离，丢弃这段阻力位移，避免突然跳高。
- 0.5.4 的单手“捏住移动展台”把手立即接管，不再等待 0.28 秒双手配对窗口；第二只手仍可接管成双手操作。其他零件/按钮保留原配对保护。贴桌时提示上提脱离进度，空中不施加桌面提起阈值。
- 脱离后设 0.6 秒冷却；同一次抓取需先离开 11 厘米邻域，再靠近才重新吸附。松手允许重新放回。
- 吸附后锁定高度，避免扫描抖动带动模型；感知暂停/消失时保持已放置位置，仍可主动提起。
- `SwanTwoHandManipulation` 在受约束时重置内部目标，避免隐藏的位移、角度或尺寸积累造成松手跳变。FPS 根节点保持独立。
- 应用暂停/组件禁用时取消回调，停止并销毁本组件创建的网格子系统；原有子系统只恢复自身启动的运行状态。
- 首次启动请求空间数据权限；拒绝后本次会话不重复弹出，用户仍可手动移动展台。授权弹窗导致的 Activity 暂停结束后重新检查授权状态。
- 0.5.1 用户在头显亲自允许权限后，曾出现高亮正常但应用手势失效。正常重启应用后，点击、拆装、推把和双手操作恢复，日志记录应用更新约 89.9–90.1 Hz、头部追踪正常。0.5.2 在返回应用后通过 SDK 公开方法重新同步 Spatial 模式；这个修正仍需实际返回流程验证，不能把重启恢复等同于修复验收。

## 验证与日志

Play Mode 检查：`SwanTabletopChecks`。覆盖世界坐标变换、排除地面和斜面、扫描小缝隙容错、较大空洞拒绝、底部偏移、单/双手粘滞提起、空中无桌面阻力、连续脱离、重新放置、平移/旋转/缩放、桌边阻挡、数据移除与追踪丢失。`SwanAtelierGestureChecks` 还验证实际单手把手输入在 50 毫秒内移动，第二只手可接管。现有 45 件装配、快速归位、展开动画、推把、剖面和 FPS 检查继续运行。

0.5.3 真机诊断（2026-10-26）：正常重启后持续收到真实 Table 网格；目视贴桌时底部高度 0.561m，扫描高度 0.552m，差 9mm，但精确覆盖仅 40/45 点，随后波动在 37–44 点。直到约 23 秒后才出现 `SWAN_TABLE_ATTACH`，证明严格覆盖造成明显迟滞，并非统一坐标偏移。后续亦记录到双手移动中的再次吸附。用户仍报告双手粘滞不明显、单手在空中也有启动迟滞，因此未把此版本标记为完整体验验收。一次更新后的启动没有任何扫描回调，正常重启才恢复；此启动间歇问题尚未证明根治。

0.5.4 诊断：即使放宽边缘 5cm，覆盖仍有 39–43/45，发生延迟吸附。在休眠状态开始加载的进程没有网格回调；保持佩戴唤醒后正常重启，回调恢复。日志显示自动 XR Loader 在场景和佩戴恢复之前完成 Initialize。0.5.5 禁用 BeforeSplash 的自动初始化，改由 `SwanSpatialInputMode` 在 Start 后一帧、应用获得焦点且 SpatialCamera 已存在时，通过 Unity XR Management 4.4 的公开 `InitializeLoaderSync` / `StartSubsystems` 启动同一个 PXR_Loader。感知等待 Ready 后再启动；销毁时停止/释放本组件拥有的 Loader。没有切换普通 XR 渲染，也没有重新初始化已工作的 Loader。此时序修正需要真机冷启动/唤醒验证，不能仅以编译通过视为已解决。

0.5.5 真机仍无网格回调，用户确认操作正常但不吸附；因此时序调整不能视为根因修复。0.5.6 参考已安装 AR Foundation 5.1.5 的 `ARMeshManager.Update/UpdateMeshInfos`，补上公开 `XRMeshSubsystem.TryGetMeshInfos` 的 5Hz 主动查询，复用列表，仅记录更新与接收语义回调，不生成房间渲染器或碰撞器。`SWAN_TABLE_POLL` 区分 provider 的查询结果、更新数量及实际回调次数；此修正也必须等待真机结果。

0.5.6 实测仍未解决：佩戴唤醒并观察茶几时，主动查询持续 `success=False infos=0 callbacks=0`，手部操作与头部姿态仍正常。当前版本仅为**调试备份点**，不能标记桌面吸附完成。2026-10-27 用户要求先提交并上传当前工程；后续最小感知验证应置于独立目录，不继续混入主工程。旧的 0.4.3 提交 `75dad7b4ecafa418d2252cf3a9953f88efb88873` 保留为此前版本的回退点。原始搭档场景哈希未变化。

Android/真机检查记录在本次交付报告中，不能由编辑器检查替代。日志前缀：`SWAN_TABLE_DESCRIPTORS`、`SWAN_TABLE_SENSOR`、`SWAN_TABLE_SCAN`、`SWAN_TABLE_ALIGNMENT`、`SWAN_TABLE_GRAB`、`SWAN_TABLE_RESIST`、`SWAN_TABLE_RELEASE`、`SWAN_TABLE_ATTACH`、`SWAN_TABLE_DETACH`。ALIGNMENT 的 covered 是原精确覆盖数，supported 是加入有界容差后的覆盖数。`SWAN_ATELIER_FPS` 为应用更新频率，不代表原生合成器帧率。
